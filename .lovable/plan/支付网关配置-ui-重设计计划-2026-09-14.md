# 支付网关配置 UI 重设计计划

## 目标
把当前空白首页改造成支付网关管理控制台，依据现有后端能力呈现 Provider、渠道、商户、凭据版本、路由权重与故障恢复。

## 设计方向
- 采用已选的 **Control-room calm** 构图：可折叠侧栏、顶部操作栏、状态总览、路由权重、凭据版本与恢复队列。
- 保留此前锁定的视觉要求：墨黑珊瑚配色（`#F8F7F4 / #1C1B1A / #E05A47 / #247A83`）、JetBrains Mono 标题、Work Sans 正文。
- 桌面端强调高密度扫描；窄屏改为抽屉侧栏和纵向内容，不产生遮挡。
- 状态、风险与只读信息使用不同语义颜色；危险操作不依赖颜色单独传达。

## 页面内容
1. **全局框架**
   - 支付网关品牌区、可收起导航、当前角色与强认证状态。
   - Overview、Providers、Channels、Merchants、Credentials、Routing、Recovery、Audit log 导航。
2. **运行总览**
   - 在线渠道、总权重、失败事实、凭据版本四项指标。
   - 顶部搜索、待处理提醒与“新建版本”入口。
3. **路由配置**
   - 展示 `mock`、`flrqfpay`、`peqorapay` 渠道、权重、READY 状态和启停状态。
   - 支持选择渠道、调整演示权重，并明确 `0..10000` 范围与版本锁提示。
4. **商户与凭据版本**
   - 展示 ENABLED 商户、READY/PENDING/RETIRED 版本与脱敏摘要。
   - 新建版本使用分步弹窗；Secret 输入后不再回显。
5. **恢复中心**
   - 分开展示失败事实投递与停止查单渠道腿。
   - 重试/恢复操作要求填写原因，并显示强认证要求与确认步骤。
6. **权限和安全反馈**
   - SUPER_ADMIN 显示写操作；SUPPORT_OPERATOR 演示只读状态。
   - 渠道代码不可变、归档冻结、并发版本冲突等规则在操作上下文中提示。

## 交互范围
- 完成导航切换、侧栏折叠、搜索/筛选、渠道选择、权重编辑、版本创建弹窗、恢复确认弹窗和只读角色切换的前端交互。
- 使用可信模拟数据演示现有后端合同；本轮不连接或修改 `baijiebot/videoadmin` 后端接口。

## 技术与验收
- 使用项目现有 TanStack Start 与 Tailwind v4，并建立语义化设计变量。
- 首页补齐独立标题、描述及社交分享元信息。
- 检查桌面与手机布局、键盘焦点、对比度、弹窗操作和内容溢出。
- 通过项目自动检查，并用浏览器截图验证最终页面。
